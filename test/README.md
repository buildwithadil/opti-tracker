# Phase 1–6 backend and browser tests

Run `npm test` from the project root. These tests execute in **workerd** through the installed Cloudflare Vitest integration; HTTP tests call the actual worker via `cloudflare:test`'s `SELF` binding and database tests use its real D1 binding. No Node-only D1 mock or router mock is used.

The root Vitest configuration supplies `TEST_MIGRATIONS`, `DB`, `SESSION_PEPPER`, and `SETUP_TOKEN`. The installed package is `@cloudflare/vitest-plugin` (the newer package exposing `cloudflare:test`, rather than the older `@cloudflare/vitest-pool-workers`). `test/helpers.ts` contains references to its installed runtime types.

## Database isolation

Each standard database-backed file resets Cloudflare test bindings and applies migrations once in `beforeAll`; historical migration suites intentionally start at their earlier checkpoint per case. Before each individual test, the fixture removes only test rows with foreign keys enabled. It temporarily drops exact original immutable cleanup guards, removes invoices then number reservations before payments/items/purchases and their referenced audits, and removes clinical descendants before roots. It restores **original migration SQL** in `finally`; no substitute guards are installed. Production databases are never cleaned. Restrictive FKs determine cleanup order. Focused FK/index/read-model tests restore any temporarily removed guard/view exactly. Five intentional skipped-audit deferred-FK failures emit expected workerd/Miniflare rollback diagnostics; assertions confirm pre-existing test records survive. Migration ledgers are retained and checked for idempotence.

The tests are intentionally serial per the root configuration. Avoid `.concurrent` test declarations that would share and reset the same D1 binding. The concurrent bootstrap/login assertions instead send concurrent HTTP requests *within* one isolated test.
