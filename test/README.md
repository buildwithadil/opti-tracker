# Phase 1–4 backend and browser tests

Run `npm test` from the project root. These tests execute in **workerd** through the installed Cloudflare Vitest integration; HTTP tests call the actual worker via `cloudflare:test`'s `SELF` binding and database tests use its real D1 binding. No Node-only D1 mock or router mock is used.

The root Vitest configuration supplies `TEST_MIGRATIONS`, `DB`, `SESSION_PEPPER`, and `SETUP_TOKEN`. The installed package is `@cloudflare/vitest-plugin` (the newer package exposing `cloudflare:test`, rather than the older `@cloudflare/vitest-pool-workers`). `test/helpers.ts` contains references to its installed runtime types.

## Database isolation

Each database-backed file resets Cloudflare test bindings and applies migrations once in `beforeAll`. Before each individual test, the fixture removes only test rows with foreign keys enabled. To permit cleanup, it temporarily drops the exact original audit-delete, issued-purchase-delete, customer-delete, prescription-delete and purchase/item immutable cleanup guards, removes items then purchase headers then their referenced audits, and removes clinical descendants before roots. It restores **original migration SQL** in `finally`; it does not install substitute guards. Production databases are never cleaned. The new restrictive audit FK determines the cleanup order. Focused FK/index tests retain genuine constraints and restore any temporarily removed guard exactly. Two intentional skipped-audit deferred-FK commit failures emit expected workerd/Miniflare rollback diagnostics; assertions confirm original owner/customer/audit records survive. Migration ledgers are retained and checked for idempotence.

The tests are intentionally serial per the root configuration. Avoid `.concurrent` test declarations that would share and reset the same D1 binding. The concurrent bootstrap/login assertions instead send concurrent HTTP requests *within* one isolated test.
